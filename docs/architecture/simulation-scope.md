# 仿真复杂度、阶段目标与边界

## 1. 定位

PLC2Agent 的仿真目标是验证 PLC 控制工程，不是成为通用物理引擎。

无论接入多少种模拟器，核心问题始终限定为：

- I/O 与设备语义是否正确；
- 扫描周期、时序和顺控是否正确；
- 模式、联锁和安全不变量是否成立；
- 报警、故障锁存和恢复流程是否正确；
- Runtime、Plant 与需求之间是否有可重放证据；
- Agent 能否根据诊断和 Trace 修改 PLC 工程并重新验收。

三维画面、机器人动力学、液压、热力和流体模型可以提供更丰富的被控对象，
但不能改变上述核心边界，也不能成为 PLC 工程的唯一事实来源。

## 2. 复杂度分级

下表是阶段性工程目标，不是已经测得的性能上限。

| 层级 | 可以做到什么 | PLC2Agent 的位置 |
|---|---|---|
| 单机级 | 电机、传感器、气缸、按钮、急停 | 已具备基础闭环 |
| 单元级 | 2～5 段输送带、分拣、缓存、多物料 | 下一阶段内建 Plant 主目标 |
| 产线级 | 多工位、约 100～300 I/O、配方、报警、区域安全 | 后期内建离散仿真主目标 |
| 小型工厂级 | 多 PLC、多产线、共享物流和资源调度 | 可做离散逻辑与通信仿真 |
| 高精度数字孪生 | 机器人动力学、液压、热力、流体、柔性物体 | 通过外部 Plant Adapter 接入 |
| 工艺工程仿真 | 化工过程、电网暂态、CNC 切削、真实碰撞精度 | 交给专业仿真器，PLC2Agent 只接控制与证据接口 |

## 3. 阶段目标

### S0：单机闭环

能力：

- 单电机或单输送带；
- 数字输入输出；
- 启动、停止、换向；
- 急停锁存与安全复位；
- 编译后的 ST Runtime；
- Modbus 与三维场景反馈。

当前状态：已由 ACC Conveyor + STruC++ 实验证明。

退出条件：真实 Plant 反馈能够驱动 ST 状态转换，且测试、变量轨迹和最终状态一致。

### S1：自动化单元

建议规模：

- 2～5 段输送带；
- 10～30 个设备组件；
- 20～40 个 I/O；
- 2～3 种物料；
- 多物料同时在制；
- 推杆、缓存、分流和下游背压；
- 传感器卡死、执行器卡死、延迟和通信中断。

首个目标采用现有 `specs/plant.yaml` 中的双输送带 A/B 箱体分拣单元。

退出条件：至少 10 个物料连续运行；正常、急停、堵塞和卡死场景自动通过；
相同种子产生相同 Trace。

### S2：自动化产线

建议规模：

- 多工位串并联；
- 约 100～300 个 I/O；
- 10～100 个并发物料；
- 自动、手动、维护和故障模式；
- 产品配方、换型、报警和区域安全；
- 工位握手、缓存容量和节拍约束。

退出条件：Agent 能发现至少一个跨工位时序或联锁缺陷，修复后重跑核心 FAT；
每项结论均能定位到需求、构建、场景和 Trace 区间。

### S3：小型工厂离散仿真

建议规模：

- 5～10 个自动化单元；
- 多 PLC 或多控制任务；
- 多产线共享物流、缓存和设备资源；
- 控制器握手、网络延迟、掉线和重启；
- 班次、批次与基本产量统计。

退出条件：能够验证跨 PLC 协同、网络故障和共享资源竞争；局部故障不会传播成
未受控的全厂动作。

### S4：外部高精度数字孪生

本阶段不扩写内建物理内核，而是接入一个或多个已有模拟器。可选能力包括：

- 三维碰撞与空间布局；
- 机器人轨迹和动力学；
- 真实设备模型或厂商场景；
- 高精度工艺反馈。

退出条件：同一份 PLC I/O 契约可以在内建确定性 Plant 和至少一个外部模拟器间
切换；外部场景的运行仍能产生结构化 Trace 和可审计验收结果。

### S5：专业工艺仿真接入

化工、热力、流体、电网暂态和 CNC 等模型由专业工具负责。PLC2Agent 仅负责：

- 信号与单位映射；
- 时间同步和采样策略；
- Runtime 控制接口；
- 场景启动与故障编排；
- Trace、诊断和 FAT 证据归一化。

退出条件：专业仿真器可以被当作 Plant 后端使用，而无需把其物理模型复制进本仓库。

## 4. Plant Adapter 边界

所有内建或外部模拟器都通过同一类边界参与闭环：

```text
PLC program / SoftPLC
          |
          | inputs / outputs / scan metadata
          v
Runtime Adapter
          |
          v
Canonical Plant Contract
          |
          +--------> Built-in deterministic Plant
          |
          +--------> ACC / Factory-style 3D scene
          |
          +--------> Robotics / physics simulator
          |
          +--------> Professional process simulator
```

Plant Adapter 最小能力：

```text
capabilities
reset
read_inputs
write_outputs
run or step
get_state
get_time
get_trace
```

可选能力：

```text
snapshot / restore
inject_fault / clear_fault
spawn / remove material
accelerated_time
seeded_replay
coverage metadata
```

Adapter 必须声明：

- 时间模型：实时、固定 tick、事件驱动或混合；
- 是否确定性；
- 是否支持加速、暂停、快照和恢复；
- 可注入哪些故障；
- I/O 更新和 PLC scan 的同步方式；
- 状态与 Trace 的精度和缺失项；
- 连接目标为 `simulation`、`softplc` 还是 `physical`。

## 5. 防止领域漂移

一个新模拟器只有满足下列至少一项时才进入主路线：

1. 能验证新的 PLC 控制模式、时序或安全性质；
2. 能提供当前 Plant 缺失的设备或工艺反馈；
3. 能作为同一 PLC 程序的兼容性或回归后端；
4. 能产生 Agent 可读取的结构化状态、诊断或 Trace；
5. 能提高故障注入、重放或 FAT 的可信度。

下列工作不进入核心：

- 为展示效果自研通用三维编辑器；
- 复制专业机器人、流体、热力或电磁求解器；
- 只支持鼠标点击、无法脚本化和取证的场景；
- 与 PLC I/O、控制逻辑和验证无关的通用游戏或物理内容；
- 让外部工具的私有工程格式污染上层控制契约。

## 6. 规模不是唯一指标

仿真难度由四个轴共同决定：

- 设备规模：组件、I/O、物料和控制器数量；
- 物理精度：离散状态、运动学、动力学或连续过程；
- 并发与时序：工位协同、缓存、节拍、网络和扫描周期；
- 故障空间：卡死、抖动、延迟、掉线、重启和组合故障。

PLC2Agent 优先提升并发、时序和故障验证能力。设备数量可以逐步增加；物理精度
只有在影响控制结论时才增加，并优先通过外部 Adapter 获得。
